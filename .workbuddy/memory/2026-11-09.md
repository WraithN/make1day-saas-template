## TopProgressBar 报错修复（用户贴 dev overlay：`useInsertionEffect must not schedule updates`）
- **根因**：`components/TopProgressBar.tsx` monkey-patch 了 `history.pushState/replaceState`，Next App Router 会在 React `useInsertionEffect` 同步阶段调用它们；wrapper 里同步 `setVisible(true)` 直接违反插入阶段禁更新约束。另有隐藏 bug：旧 `urlChanged()` 把相对路径 `/templates` 与完整 `window.location.href` 直接字符串比较 → 恒不等，Next 内部 no-op 的 `replaceState` 也被误判成"导航开始"，进度条误闪且反复撞进插入阶段。
- **修复**（提交 `5cef9cd`）：`begin()` 的所有 setState 挪进 `queueMicrotask`（脱离 commit 阶段）；`isNoopUrl()` 用 `new URL(String(url), location.href).href` 规范化后比较；`BarState` ref 集中管理 pending/scheduled/alive/raf/timer，去重微任务、取消陈旧 rAF/隐藏定时器、防卸载与预取快速导航卡住；END effect 与 microtask 的竞态由 `pending` 标记收敛。
- **顺带修客户包缺陷**：`TopProgressBar` 不在裁剪清单 → 会随客户 ZIP 发布，但客户 CSS 由 `themes.ts:buildGlobalsCss()` 生成、不含 `.sk-progress`，进度条在客户站是看不见的裸 div。已在 `STATIC_CSS` 补 `.sk-progress`/`.sk-progress-bar`（用 `rgb(var(--accent))`，客户主题变量里存在）。
- **验证**：`tsc --noEmit` EXIT 0；干净 `next build` EXIT 0（6 个模板预览页 SSG）；矩阵 **18/18**（`--base http://127.0.0.1:3100`）；`npm run smoke` **48/48**（gate 20 + ai-quota 12 + supabase 6 + stream 10）；Playwright 实测 dev + 生产两套：no-op `replaceState` 不再触发进度条、3 次真实客户端导航（模板卡片 / 返回画廊 / Nav 链接）进度条正常挂载、`INSERTION_EFFECT_ERRORS=0`、控制台 0 错误。
