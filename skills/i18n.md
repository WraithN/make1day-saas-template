# Skill: i18n — five languages (ShipKit)

## Architecture
- `lib/i18n-core.ts` — the dictionary: five complete locales (`en`, `zh`, `ja`, `fr`, `de`) plus `interpolate()`.
- `lib/i18n.tsx` — client `LanguageProvider`, `useLanguage()`, `<Trans k vars />`, `data-i18n-vars`.
- `lib/i18n-server.ts` — `getLang()` / `tr()` for Server Components; reads `x-sk-lang` header first, then `sk_lang` cookie.
- `middleware.ts` — `?lang=` seeds the cookie and forwards `x-sk-lang`; it does **not** 308-redirect (crawlers need the query URL).
- `components/SeoLinks.tsx` — per-page canonical + hreflang, rendered *inside* `LanguageProvider`.

## Rules
- **All five locales are complete.** Do not add an `en`-only key, and do not assume `ja`/`fr`/`de` fall back to English.
- New keys are namespaced and lowercase: `feature.rag.title`, `builder.pay.waffo.note`.
- Dynamic values use `{var}` placeholders + `interpolate()`, e.g. `pricing.poweredBy` → `"Payments by {provider}"`. Escape happens in `interpolate`; never concatenate raw HTML.
- Highlight markup uses `{{g}}…{{/g}}`, handled by `applyMarkup()`. Do not embed JSX in dictionary values.
- `<html lang>` follows the active locale. `?lang=` must stay in canonical/hreflang URLs so localized pages are indexable separately.
- Root layout cannot receive `searchParams`; language arrives through the middleware header. Do not "simplify" this away.

## Do / Don't
- DO add long-tail copy to FAQ / Compare / Blog rather than only to the landing hero.
- DO update `llms.txt` facts when product copy changes.
- DON'T hardcode marketing strings in a page component.
- DON'T translate code identifiers, env names or API field names.

## Verify
Switch all five languages in the UI → reload `/?lang=zh` → view source and confirm `<html lang="zh">` + Chinese hero text + hreflang set.
